# 报告结构与框架覆盖

## 目录

1. 用户框架优先

## 1. 用户框架优先

用户提供目录、章节公式、评分表或样文时，先建立覆盖表：

| 用户要求 | 对应章节 | 拟填内容 | 证据来源 | 状态 |
|---|---|---|---|---|

在覆盖表完成前不要自由改造目录。允许合并、改名、调整顺序或省略时，记录原因并向用户说明。

不要把框架只当作语气或风格参考。用户指定的表达公式也要逐项覆盖，例如：

- 结果 + 对比 + 价值；
- 问题 + 影响 + 原因 + 措施 + 验证标准；
- 目标 + 指标 + 动作 + 时间节点。

## 2. 默认五章结构

用户没有指定框架时，优先采用下面的竞赛调研结构。

### 第一章：背景、问题与研究设计

任务：说明为什么研究、具体回答什么、材料从哪里来、结论边界是什么。

避免：大段政策口号、行业百科、与核心问题无关的文献堆叠。

### 第二章：调研对象与真实实践

任务：客观呈现主体已经做了什么、目前进展和可观察事实。

避免：提前解释原因、提前给对策、把走访过程当成果。

### 第三章：差异比较与机制解释

任务：横向比较案例，说明共同点、差异、反例及形成机制。

避免：重复第二章事实、罗列若干独立案例、用理论名词代替解释。

### 第四章：分类行动与公共支持

任务：让每项行动回到前文发现和机制，明确主体、适用条件和验证方式。

避免：统一药方、空泛倡议、只写政府做什么、不核实现有政策。

### 第五章：结论、成果与研究边界

任务：回答核心问题，列出已形成成果，说明样本、方法和适用范围。

避免：把摘要重复一遍、夸大推广价值、隐藏不确定性。

## 3. 产业与企业调研变体

推荐结构：

1. 产业变化与具体问题；
2. 企业样本的现有基础和转型实践；
3. 企业能力、客户基础或阶段差异；
4. 路径分化的形成机制；
5. 企业分类行动与公共支持；
6. 最小验证、成果和边界。

使用「客观位置 + 能力差异 + 动作组合」，避免把每家企业强行塞入一个互斥类型。

## 4. 社区与公共治理变体

推荐结构：

1. 制度目标与基层场景；
2. 政策文件中的规定；
3. 实地执行方式和典型案例；
4. 文件规定与实际运行的落差；
5. 主体关系、激励与治理机制；
6. 分类改进方案和适用条件。

将政策文本和现场观察放在同一分析框架中比较。

## 5. 文化传承与乡村实践变体

推荐结构：

1. 文化或产业对象的真实生存状态；
2. 传承、生产、市场和组织主体；
3. 不同地区、流派或经营模式比较；
4. 衰落、转型或传播困难的机制；
5. 保护、活化和市场边界；
6. 青年参与方式与长期验证。

避免把文化价值直接等同于市场价值。

## 6. 章节边界

为每章写一句「本章只做什么」：

- 事实章只回答「发生了什么」；
- 比较章只回答「哪里相同、哪里不同」；
- 机制章只回答「为什么」；
- 对策章只回答「谁在什么条件下做什么」；
- 结论章只回答「报告最终能确认什么」。

相同材料可以在不同章节被引用，但不能重复讲述。事实章呈现材料，机制章提取其解释作用，对策章只引用足以支撑行动的部分。行动、路径、政策动作等结构性内容必须放在对策章；当其出现在事实、比较或机制章时，只能作为分析对象，不提前写成建议或实施方案。

## 7. 篇幅分配

按任务调整，不固定套用。先设总字数预算，再同时给出百分比和绝对字数预算；交付时报告实际字数与预算差额。一般参考：

- 背景与方法：10%至15%；
- 事实与实践：20%至25%；
- 比较与机制：25%至35%；
- 对策与验证：20%至30%；
- 结论与边界：5%至10%。

报告越短，越要压缩背景，优先保留一手发现、机制和行动闭环。
