## 1. 质量观

竞赛调研报告不是材料汇编，也不是长篇政策综述。它需要完成四件事：

1. 从真实调研中发现一个具体问题；
2. 用多类证据说明问题如何发生；
3. 解释不同案例或主体为何出现差异；
4. 提出与行动主体能力、当地条件和证据强度匹配的方案。

质量主要取决于：

- 哪些信息值得进入正文；
- 现有证据最多支持什么结论；
- 样本与材料边界是否诚实；
- 结论是否能帮助企业、政府、社区或其他主体行动。

吸收三类报告的优点：

- 竞赛型报告：真实走访、原创发现、青年视角；
- 政策型报告：机制、行动主体、分类建议、验证方式；
- 学术型报告：样本、方法、证据和研究边界。

避免把报告写成长文献综述、行业百科或没有基础数据的商业咨询报告。

## 2. 论证主链

默认主链：

```text
原有认识
→ 实地调研
→ 反常或差异
→ 案例比较
→ 机制解释
→ 分类行动
→ 验证方式
→ 适用边界
```

检查核心问题：

- 现有调研材料能否回答？
- 当地行动主体是否关心？
- 如果只靠宿舍上网也能写出来，实地调研价值是否过弱？

## 3. 调研反转

使用三步提炼：

1. 原先以为是什么；
2. 调研后发现哪里不一致；
3. 这个差异把研究问题改成了什么。

安全表达：

> 调研前，团队主要关注……；实地材料显示……。因此，报告不再笼统讨论……，而是转向回答……。

反转必须来自一手材料或可核查差异，不得为了竞赛感虚构冲突。

## 4. 案例比较

不要把多个对象写成多篇独立简介。统一使用可比较维度，例如：

| 对象 | 原有基础 | 已采取动作 | 当前进展 | 关键约束 | 可验证下一步 |
|---|---|---|---|---|---|

先找共同点，再找差异，最后寻找反例。案例只保留能支持结论、挑战结论或解释边界的细节。小样本且涉及敏感主体时，按 `evidence-rules.md` 的授权与匿名规则处理，避免由「业务特征 + 问题 + 时间」组合反向识别对象。

## 5. 机制解释

用完整因果链表达：

```text
可观察条件
→ 主体选择或行为
→ 中间约束、激励或能力变化
→ 可观察结果
```

两项检查：

1. 删去地名和行业名后，如果表述仍适用于所有地方，说明机制过于泛化。
2. 主动寻找不符合预期的案例。反例用于修正机制，不要因其“不整齐”而删除。

将机制性解释写成「初步机制判断」「案例显示」「材料共同指向」，除非证据足以支持更强因果结论。

## 6. 对策设计

使用闭环矩阵：

| 调研发现 | 证据 | 形成原因 | 行动主体 | 具体行动 | 公共支持 | 验证方式 |
|---|---|---|---|---|---|---|

分类至少考虑：

- 不同规模、阶段、能力或资源基础的主体；
- 企业、政府、行业组织、学校和青年团队的不同职责；
- 短期可执行动作与中长期制度建设。

不写「加强宣传、加大投入、完善机制」等无主体、无动作、无验证的句子。

## 7. 青年视角

把青年放入因果链：

```text
调研发现青年相关问题
→ 解释其如何影响产业或治理结果
→ 明确青年能承担的具体角色
→ 形成可验证产出
```

可用角色包括持续跟踪、数字化整理、传播翻译、人才连接、轻量工具试验和反馈机制。正文保持客观克制，返乡身份可以成为观察位置，但不能替代证据。
