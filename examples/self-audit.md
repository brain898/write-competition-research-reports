**这里有一个必须区分的判断。** 后三条都返回了空状态码，但性质完全不同：

- 人大 SARD 那条，服务器正常响应并明确返回了 nginx 404 页面，站点根目录本身是 200。这是**资源确实已被删除**。
- 西南科技大学那条是 TLS 握手在传输层就失败了，跳过证书校验仍然拿不到响应。
- 挑战杯官方项目库那条是 40 秒超时，没有收到任何字节。

后两条是**当前网络环境到该站点不通**，不是内容失效。按本 skill 的规则，这两条应标为「当前环境无法核实」，不得据此降级已经写入的判断，也不得当成死链删除。把连接失败当成页面失效，和把 404 当成「可能只是暂时打不开」，是同一类错误的两个方向。

## 检查二：引文能否回到原文

`style-examples.md` 第 2 节引用了京东报告的一句话，用引用块标成了短摘录：

> 「成本地板不断抬升，销售价格受到天花板封顶。」

由于原始链接已 404，按规则必须回查存档。Internet Archive 存有两份快照：2024-08-17（8.6 MB，完整可读）与 2025-09-05（5.0 MB，xref 表损坏，无法解析）。取前者提取全文核对，原文实际是分属两个自然段的两句话：

> ……而是生产效率远高于农业的城市部门顶推着农业生产经营的「成本地板」不断抬升。
>
> 另一方面，国内农产品的销售价格还受到国际市场价格「天花板封顶」的影响，农产品价格甚至一定程度上出现了「地板」高于「天花板」的倒挂情况。

**认定：这是一条不合规引用。** 它把跨段的两句话缩写拼接成一句，加引号呈现为直接引语。`evidence-rules.md` 第 7 节写明「引用转写前回到原始录音或原文核对；无法核对时标为转述」。原文的意思没有被歪曲，但形式上它是转述而不是直引，不该用引用块加引号呈现。

同时确认了报告身份可核实：课题组首席专家温铁军（中国人民大学教授、可持续发展高等研究院执行院长），主持人董筱丹（农业与农村发展学院副教授），2023 年发布，21 世纪经济报道 2023-09-21 有公开报道佐证。

`style-examples.md` 与 `sample-deconstructions.md` 都标注「访问日期：2026-07-30」。但 `style-examples.md` 的文件修改时间是 2026-08-14，内容改过而访问日期没动。

`evidence-rules.md` 第 8 节要求「记录页面标题、发布机构、发布日期、链接和访问日期」。访问日期的作用是让读者判断这条核验有多新；不随内容更新，这个字段就失去意义。

## 这次自查说明了什么

第一，**死链是必然的，不是意外。** 6 个来源用了不到一年就死了 1 个、2 个无法核实。任何写进报告的网络来源都会走这条路，所以规则不能只写「记录链接」，得写「记录到什么程度才算可回溯」。

第二，**最难发现的不是死链，是形式上合规的引用。** 那条拼接引语在文件里躺了很久，读多少遍都读不出问题，只有真的把原文拉下来逐字比对才会露馅。这也是为什么 `evidence-rules.md` 要单列「成稿后事实抽查」一节：抽查的动作是打开原始材料，不是重读自己的稿子。

第三，**绿色不等于健康。** 三个链接返回 200 就以为没事，是这次检查一开始差点犯的错。真正的判断来自逐条看响应内容和失败原因。

## 检查四：README 首屏的徽章和链接

`README.md` 顶部的 skills.sh 徽章，实际渲染结果是一枚红色的报错标签：

curl -s -L "https://skills.sh/b/brain898/write-competition-research-reports" | grep -o 'aria-label="[^"]*"'

**两个独立的问题叠在一起。**

第一个是**写错了**：skills.sh 的 skill 页面路径带 `/s/`，README 里的链接漏了，指向 404。这是笔误，改掉即可。

第二个**不是写错**，需要区分。`/b/{owner}/{repo}` 是 skills.sh 的安装计数徽章端点，它本身工作正常：

```bash

  curl -s -L "https://skills.sh/b/$r" | grep -o 'aria-label="[^"]*"' | head -1
done
# → aria-label="Skills: 27.4K"
# → aria-label="Skills: 81"
# → aria-label="custom badge: resource not found"
```

端点对别人返回真实计数，对本 skill 返回「resource not found」，说明是**本 skill 在该系统里还没有计数数据**，不是 URL 拼错。这和第一轮区分「404」与「TLS 握手失败」是同一类判断：**同样是拿不到东西，原因不同，处理方式就不同。**

按 `evidence-rules.md` §8「查不到时明确写未核实或删除，不补造看似合理的来源」，处理是：拿不到的数字就不显示。徽章换成不承载数字的静态标记，链接指向正确的 `/s/` 页面。等真有安装量再换回动态徽章。

## 检查五：examples 里的数字能否回算

`before-after.md` 末尾的「字数账」写着「Before 172 字，After 486 字」。实际回算：

| | 文档原写 | 字符数（不计空格） | 其中汉字 |
|---|---:|---:|---:|
| Before | 172 | 201 | 182 |
| After | 486 | 432 | 388 |

两个数字都对不上任何一种口径，**且误差方向相反**（一个少算 29，一个多算 54），排除了口径差异的可能，说明是估的不是算的。

这条比死链更难发现。死链 curl 一下就露馅，字数账看多少遍都看不出问题，只有真的跑一遍才知道。这正是 `evidence-rules.md` §9 单列「成稿后事实抽查」的理由：**抽查的动作是回到原始材料重算，不是重读自己的稿子。**

处理：改为回算后的真实数字，补上计算口径（字符数不计空格、含标点、剔除 Markdown 引用符号），并把复现命令写进文件，任何人可以自己跑。

## 第二轮说明了什么

第一轮的三条结论仍然成立，第二轮补两条。

第四，**自查范围会自己缩水。** 第一轮定的范围是「`references/` 全部参考文件」，看起来很彻底，其实漏掉了读者第一眼看到的 README 和 examples。范围定得越具体，越容易把范围外的东西当成不存在。下次定范围先问一句：读者最先看到的是哪个文件，它在范围里吗。

第五，**最难查的数字不是引来的，是自己算的。** 第一轮查出的问题是别人页面死了、别人的话被拼接了，源头在外部。第二轮查出的三个问题全部源于自己：自己写的徽章、自己算的字数、自己跑的测试。外部来源至少还有个原始出处可以回去核对，自己产生的数字如果当时没留计算过程，事后连回去核对的对象都没有。所以规则不是「写完要核对」，是**写的时候就把计算方法一起写下来**。

## 检查七：0/5 是怎么来的

本地记录显示，对照组不是一轮跑出来的。首轮五条全跑，结果是通过 3、失败 2。通过的那三条说明它们测的是模型通用能力，对「本 skill 是否生效」没有区分度，于是各加严一条红线后重跑，三条全部失败，且各自只触碰新增的那一条。

所以 0/5 由五次判分构成，取自两轮共八次判分中的五次，其中三次的判分标准比首轮严。

两处更正：

- README 原写「**同题同日**、不装 skill 的对照组：0/5」。同日不成立（跨两轮），同题也不成立（三条的红线在两轮之间被加严过）。已改。
- 此前 README 与 `benchmark.md` 都出现过「六次判分」。已按五次口径更正，并在 `benchmark.md` §4.1 写明这五次各自来自哪一轮。**「六次」的出处后来查到了**，见下面的检查十——本轮一度断言它没有出处，那句断言本身是错的。

## 检查八：5/5 是哪把尺子量出来的

本地记录写得很清楚，README 一个字没转述：**基线在判分规则 v1 下是 4/5，v2 下才是 5/5。** 差别只在字数那条红线，它在跑测当天从「自报值与实测偏差超 3% 即失败」降级为「只判净减方向」，挂在这条上的那次因此追溯复判为通过。

降级本身有充分理由并且记录在案（该红线测的是模型逐字计数的准度，而本 skill 明确不管这件事，它已经不是区分器，只是一盏灭不掉的灯）。有问题的不是降级，是**只在本地记录里写了「任何引用基线分数的地方必须写明规则版本」，而对外的 README 引用时没写**。

改尺子会追溯抬高历史分数。4/5 变 5/5 不是 skill 变好了，是尺子变松了。这一条已经写进 `benchmark.md` §4.2，两个版本的分数一并保留，同时记下降级的副作用：那条探针此后只能检出退步，无法再检出进步。

## 检查九：回填不了的字段怎么办

- **第二轮对照组日期**：本地记录标为 2026-08-17，而它所验证的加码标为 2026-08-18，时序上矛盾。两个日期都写在记录里，无法判断哪个是笔误，标「待核」。

## 检查十：回填出来的新文件，自己有没有无分母的数字

前三项检查都在拿本地记录审 README。本项反过来，审刚写完的 `benchmark.md` 自己。查出三处，其中两处是本轮亲手写进去的。

**十之一 · 「六次判分没有出处」这句断言是错的。** 它的出处是 `test-prompts.json` 的 `control_run_2_summary`「关键读法」，原文写着「两轮对照组六次判分」。本轮第一次检索没找到，就写下了「与任何一种数法都对不上，六次没有出处」。**没找到不等于不存在，这是第一轮那条「拿不到内容不等于内容不存在」的第四次现身**，而且这次犯在自己的档案里，比核验别人的外链更没有借口。更正后的表述是：六次有出处，但既不等于实际发生的八次判分，也不等于计分的五条探针，记录内部对不上，作者裁定按五次口径，`control_run_2_summary` 那处标为待更正。

**十之二 · `benchmark.md` §2 的「探针覆盖的红线」映射表是自造的，而且造错了。** `test-prompts.json` 里每条探针的 `red_lines` 用的是**探针内部的局部编号**，`SKILL.md`「最高优先级约束」用的是另一套编号，记录里从来没有一张把两者对起来的表。本轮把局部编号当成了约束编号直接引用，结果错了三处：把约束 6（不把克制措辞润色成确定说法）写成了约束 5；把「链接核验分层」当成第六条约束列了进去，而六条最高优先级约束里根本没有这一条；真正的约束 5（段落式正文与列表化限制）整条漏掉。

**十之三 · 因此，「六条红线各有对应探针」这个结论不成立。** 逐条核对后，`SKILL.md` 约束 5 在五条探针的 `expected` 与 `red_lines` 里**零命中**（全文件检索「列表 / 分点 / 段落式 / 文风 / 简体中文」，命中数 0）。这是六条约束里唯一完全没有考点的一条，而它管的恰好是最容易被违反的行为——把行动方案和结论段写成 bullet 列表。此前它被一句概括性的「六条各有对应探针」盖住了。

三处都已在 `benchmark.md` 更正：§2 换成带来源标注的对照表并明确标出零覆盖那一行，§4.1 补六次的真实出处，§5 与 §6 同步改口径。凡「红线 N」一律改为 `T5-2` 这种带探针前缀的写法，不再与约束编号混用。

## 第三轮说明了什么

前五条仍然成立，本轮补四条。

第六，**「待填」不是一个中性状态。** 第二轮发现 5/5 缺分母，建了文件、标了待填，当时觉得已经处理妥当了。但待填字段的旁边，往往还站着已经写错的字段：真正回填之后才看见「同题同日」和缺失的规则版本这两处硬错。标待填只是承认自己不知道，不等于把知道的部分核对过了。**回填之前，引用该字段的对外表述就该先降级，而不是原样挂着。**

第七，**内部记录比对外文案严，是个危险信号。** 「任何引用基线分数的地方必须写明规则版本」这句话，白纸黑字写在本地 `TESTING.md` 里，而 README 引用同一个分数时没有执行它。写给自己看的文件里守规矩，写给别人看的文件里不守，这不是疏忽，是把 README 当成了宣传材料而不是交付物。**对外文件的证据标准应当高于内部记录，不是低于。**

第八，**补分母这件事本身也会产生新的无分母数字。** 本轮建 `benchmark.md` 是为了给 README 的 5/5 补上分母，可它自己写进去的第一版映射表，就是一张没有出处的自造表，还错了三处。修复动作和被修复的问题同属一类，不会因为动机是「补证据」就自动免检。**新写的证据文件必须和被审对象受同一把尺量，而且最好隔一道工序再审一遍**，本轮的检查十就是那道工序，它查出的三处全部来自本轮自己写的文字。

第九，**编号不是名字。** 「红线 2」在 T1 里指强因果词，在 T5 里指三个数缺一，在 `SKILL.md` 里指结论强度不超过证据强度。三套编号长得一模一样，跨文件引用时不会报错，只会静静地把结论换掉。**凡是要跨文件引用的编号，引用时必须带上它所属的命名空间**（写 `T5-2` 而不是「红线 2」），否则迟早会把一条约束的证据挂到另一条约束名下。
