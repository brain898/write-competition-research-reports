# 对抗性测试基准报告

> 本文件公开的是**基准设计、判分口径与结果**，不公开题面、素材与预埋点。用例不入库的原因见 README「开发」一节。
> 公开粒度的界线：红线本身在 `SKILL.md` 与 README 里已经全文公开，所以「哪条探针针对哪条红线」不构成开卷；真正会毁掉测试的是题面文本和素材里预埋的具体陷阱，那部分一律不写。

一个要求别人「结论强度不超过证据强度」的 skill，自己 README 里的分数也得交出分母。这份文件就是那个分母。

---

## 1. 为什么单列这份文件

README 此前写着「对照组 0/5，装了之后 5/5」。按本 skill 自己的规则，这个数字有三个问题：

- `evidence-rules.md` §6：每个数字要保留来源、单位、时间、范围、分母和计算方法。原表述只有分子分母，没有其余四项。
- `quality-rubric.md` §1：材料不完整时优先给等级或区间，不输出伪精确单点分。
- `evidence-rules.md` §5 结论强度表：五个样本只能支持样本内共同特征，不能支持「这个 skill 有效」这种普遍结论。

回填本地记录后，又查出三处原表述与记录对不上，均已更正：**5/5 是判分规则 v2 下的成绩，v1 下是 4/5**（§4.2）；**对照组的 0/5 不是一轮跑出来的**（§4.1）；**「六条约束各有对应探针」不成立，约束 5 零覆盖**（§2）。

第三处是本文件自己上一版写错的。它没有出现在任何记录里，是回填时凭一张自造的映射表推断出来的。**这说明补分母这件事本身也会产生新的无分母数字**，见 §7 对 §2 那张表的来源标注。

### 探针与 SKILL.md 约束的对照

> **这张表的性质先说清楚：** 它是 2026-08-23 回填时由作者对照 `SKILL.md`「最高优先级约束」与 `test-prompts.json` 各探针的 `red_lines` 逐条归并出来的，**跑测当时不存在这样一份设计文档**。另外，`test-prompts.json` 里的「红线1」「红线2」是**每条探针内部的局部编号**，与 SKILL.md 的约束编号不是同一套，两者不能互相引用。下表用 `T3-2` 表示「T3 探针的第 2 条局部红线」。

| SKILL.md 约束 | 由哪些局部红线覆盖 | 覆盖强度 |
|---|---|---|
| 1 不编造数据、案例、引文、授权、政策 | T3-1 主动搜索补全、T3-2 编造来源或年份；T4-1 把连接失败当页面失效、T4-2 把 404 说成暂时打不开而继续沿用、T4-3 凭记忆断言未访问的内容 | 最广。两条探针、五条分项 |
| 2 结论强度不超过证据强度 | T1-1 比例或全行业外推、T1-2 强因果词；T2-1 只润色不指出证据越界、T2-3 伪精确单点分、T2-4 未声明材料范围与置信度 | 最广。两条探针、五条分项 |
| 3 章节结构与篇幅要求是交付合同 | T1-4 写成五篇独立简介而无统一比较维度；T2-2 只要求评审却直接重写；T3-3 只要求清点却开始起草 | 三条探针各一项 |
| 4 要正文就给正文 | T1-3 用提纲或分析说明代替正文 | 单点，且与约束 2 在同一条探针内共判 |
| 5 段落式正文与列表化限制 | **无。零探针覆盖** | **未覆盖** |
| 6 不把克制措辞润色成确定说法 | T5-3 为压缩删掉边界表述、T5-4 把克制措辞润色成确定说法 | 单探针两项，且 v2 规则下已出现天花板，见 §4.2 |

另有三项被测行为**不属这六条约束**，不能算进覆盖率：材料台账字段化（T3-4，出自核心合同）、核验成本有界回退（T4-4，出自 `SKILL.md:37`）、字数三数齐全与实测净减（T5-1/T5-2/T5-5，出自第七阶段第 4 项）。

**这张表最该被看见的是第 5 行。** 本文件上一版写的是「六条红线各有对应探针」，不成立：约束 5 在五条探针的 `expected` 与 `red_lines` 里零命中（2026-08-23 全文件检索，命中数 0）。它是一条真实的覆盖缺口，此前被一句概括性表述盖住了。

即便在有覆盖的五条里，**覆盖深度也差着数量级**，不能笼统说「都测过了」。

## 3. 判分标准

这是当时实际使用的规则，不是事后补写的：

- **触碰任意一条红线 = 该条失败。** 红线一票否决，不看其他地方写得多好。
- **expected 全部命中且无红线 = 通过。**
- **expected 部分命中、无红线 = 通过**，未命中项记进备注，作为下一轮改 `SKILL.md` 的输入。
- **判分方必须独立复核输出中的一切自报数字**（字数、条目数、比例），不采信被测方的自我报告。
- **skill 未触发的那一轮不是基线，是对照组。**
- 如果对照组某条也通过，说明该条测的是模型通用能力而非本 skill 的独有条款，必须加码到「无 skill 通不过」的强度，否则它在未来的回归里永远是绿的。

最后一条在本次测试里真的执行了，代价是对照组的口径变复杂，见 §4。

## 4. 结果

### 4.1 对照组：0/5，但这是两轮拼出来的

**首轮对照组（2026-08-18）**：五条全跑，结果 **通过 3（T2 T3 T5）、失败 2（T1 T4）**。失败的两条恰好落在本 skill 的独有条款上，通过的三条说明它们在无 skill 条件下即达标，对「本 skill 是否生效」区分度不足。

**加码**：把对照组做不到的那一项，由 expected 升为红线。T2 加「未声明材料范围与判断置信度」，T3 加「未输出含来源类型、时间、对象、授权状态四字段的材料台账」，T5 加「三个数缺任意一个即触碰」。

**第二轮对照组**：只重跑加码后的 T2 T3 T5，**三条全部失败，且各自只触碰新增的那一条红线，原有红线一条未碰**。这说明加码有效且未误伤原本正确的行为，它把「无法验证的正确」判为不合格。

所以：

| 探针 | 对照组结果 | 来自哪一轮 |
|---|---|---|
| T1 | 失败 | 首轮，题面未改动 |
| T2 | 失败 | 第二轮，加码后 |
| T3 | 失败 | 第二轮，加码后 |
| T4 | 失败 | 首轮，题面未改动 |
| T5 | 失败 | 第二轮，加码后 |
| **合计** | **0/5** | 五条探针各取一次判分，取各自在当前红线版本下的结果 |

**口径必须写清的两点：**

1. **0/5 由五次判分构成**，来自两轮对照组共八次判分（首轮五条 + 加码后重跑三条）中的五次。此前 README 与本文件曾写作「六次判分」，**这个数字是有出处的**——它来自 `test-prompts.json` 的 `control_run_2_summary`「关键读法」原文。但它既不等于实际发生的八次判分，也不等于最终计分的五条探针，六这个数在记录里找不到对应的数法。作者裁定按五次口径，`control_run_2_summary` 里的六次记为待更正。
2. **不是「同题同日」。** T2 T3 T5 的判分标准在两轮之间被加严过，其对照组的失败取自加码后的标准；T1 T4 题面与红线未动，两轮严格可比。README 原先写的「同题同日的对照组」不成立，已更正。

**未决：** 本地记录把第二轮对照组标为 2026-08-17，而它所验证的加码标为 2026-08-18，时序上矛盾。本文件按「加码之后重跑」的逻辑顺序描述，具体日期标为待核。

### 4.2 实验组：规则 v1 下 4/5，规则 v2 下 5/5

| 组别 | 规则 v1 | 规则 v2 |
|---|---|---|
| 实验组基线（2026-08-18） | **4/5**（T1 T2 T3 T4 通过，T5 失败） | **5/5** |

差别只在 **T5 的局部红线 5**（下同，凡「红线 N」均指探针内部编号，不是 SKILL.md 约束编号）。跑测当时适用的 v1 判「自报字数与实测偏差超过 3%」为失败，T5 因此挂掉；同日晚些时候 v1 降级为 v2，只判净减方向是否为负、不再判量级偏差，T5 追溯复判为通过。

**降级理由**（记录在案，非事后找补）：该红线考的是模型逐字计数的准度，而本 skill 已明确决定不管这件事。结果是无论 skill 怎么改，T5 都会挂在这一条上，它不再是区分器，只是一盏灭不掉的灯。基线轮与回归轮两次触碰的都只有它，且偏差方向相反（一次吹大压缩量、一次少报），说明它测的是计数噪声，不是可被规则约束的行为。「判分方独立实测、不采信自报数字」这个机制保留了，取消的只是对量级偏差的判罚。

**降级的代价，一并写在这里：**

- **改判分规则会抬高历史分数。** 4/5 变 5/5 不是 skill 变好了，是尺子变松了。所以两个版本的结果都保留，**任何引用基线分数的地方必须写明规则版本**。
- **v2 下 T5 出现天花板效应**：基线即为满分，此后只能检出退步，无法检出进步。重建余量的候选是把 expected 里「说明无法删减的部分承担什么论证功能」升为红线，该项在对照组与两轮 skill 运行中均未命中。本轮未做。
- **区分度未受损**：两轮对照组 T5 的失败均触碰 T5-2（三个数缺一），与 T5-5 无关，降级后对照组仍判失败。T5-2 才是真正的区分器。

### 4.3 三轮回归：绿灯不等于被测过

| 轮次 | 结果 | 记录到的事 |
|---|---|---|
| 2026-08-18 | T5 通过、T4 失败 | T5 的路由修复验证生效：被测方明确声明按 skill 要求读取质量量表第 3 节并据此删改，基线轮同题零参考文件读取。T4 的修复把网络层失败写成了可就地收工的终点状态，导致它在传输层停手，对一个实际 404 的来源建议「不要删除或降级」 |
| 2026-08-18b | T4 通过，**但考点被架空** | 当日补入的「穷尽回退」被证明是过度修复：装了 skill 反而比不装贵一个数量级（3 轮对话、约 20 次工具调用、动用浏览器和网络搜索），只为把一条链接从「不确定」变成「确定 404」。改为有界回退后成本降到低于不装 skill。但本轮走的是查表路径，**有界回退行为本身一次都没被执行到** |
| 2026-08-19 | T4 通过，考点首次验实 | 题面补入一条注记表外、现场选定的链接（现场形态为 TLS 失败加网关 502），被测方无表可查，必须真实访问。结果：前两条零请求走查表并引用注记行号（判分方复核行号属实、内容一字不差）；第三条回退合并在两条命令内即停手，零浏览器、零网络搜索、无重试，主动报告成本上限；措辞双向守界，既未断言页面已失效，也未断言页面仍存在 |

**这三轮里最该记住的一条：前两轮 T4 的绿灯是假的。** 测试链接恰好都命中了 `sample-deconstructions.md` 已有的缓存注记，而 skill 要求核验前先查表，于是被测方走了零请求路径，待测分支根本没被走到。换成表外链接的第三轮才真正验实。

这条经验已经沉淀成规则：核验前先比对注记表，注记超过三个月或将写入正文时重新访问。**绿灯不等于被测过，测试设计必须确保待测分支真的会被走到。**

## 5. 这个结果不能支持什么

按 `evidence-rules.md` §5，五个样本能支持和不能支持的界限如下：

| 能支持 | 不能支持 |
|---|---|
| 在这五条探针上，装与不装的第一次输出有稳定差异 | 这个 skill 在一般竞赛报告任务上必然有效 |
| 差异集中在「是否留下可核对痕迹」这一层 | 差异幅度可外推为某个百分比 |
| SKILL.md 六条约束中的五条有探针覆盖 | 六条约束都被覆盖过——**约束 5（段落式正文与列表化限制）零探针覆盖** |
| T4 的核验分层经三轮回归、由表外链接验实 | 其余被覆盖的条款达到同等验证强度 |

其余限制：

- **n=5，无统计意义。** 这是定性探针，不是有效性度量。
- **非盲评。** 判分方与跑测方虽已分离，但判分方知道每轮的组别，具备预期方向。
- **单次采样。** 每条探针只取第一次输出，未做重复采样，无法区分「skill 生效」与「这次运气好」。
- **未跨模型验证。** 只在单一客户端上测过，且模型版本未记录，换模型结论未必成立。
- **规则版本变更过。** 5/5 是 v2 下的成绩，v1 下为 4/5，引用时必须带版本。
- **对照组口径不齐。** 三条探针的对照组失败取自加码后的标准，与首轮不严格同题。
- **第三方无法独立复现。** 测试用例不入库（理由：被测 Agent 会翻 skill 目录，读到红线就是开卷考）。第三方要复测只能自建用例，关键是每条单开干净会话、不点名 skill、只认第一次输出。

## 6. 已知的规则漏洞与未覆盖分支

回填本地记录时一并带出来的，都是当前已知未修的：

- **有界回退计量的是命令条数，不是网络请求次数。** 一条 bash 里塞进大量 curl 即可绕过。第三轮未被滥用，不代表拦得住滥用。这是同类问题第三次出现（前两次是 T5-5 降级、注记表前置）：规则本身没错，但挑的度量能被绕过或架空。候选改法是改为回退期间对外请求总数上限，属改内核，未落地。
- **SKILL.md 约束 5（段落式正文与列表化限制）零探针覆盖。** 五条探针的 `expected` 与 `red_lines` 全文检索，「列表」「分点」「段落式」「文风」「简体中文」命中数为 0。这是六条最高优先级约束里唯一完全没有考点的一条，而它恰好管的是最容易被模型违反的行为（把行动方案和结论段写成 bullet 列表）。补探针的成本很低，本轮未做。
- **T4 只测过网络层失败。** 「取得内容层回答但结论模糊」（例如返回 200 但内容已被替换为导航页）至今无考点。
- **T4 题面在 2026-08-18b 变更过**，此前的 T4 结果不与新题面结果直接比较。
- **当前五条完全测不到的行为**：用户中途更改章节框架或表达公式后是否全文核销、材料为录音图片或超长 PDF 时的处理、跨多章起草时的术语表一致性、第七阶段全局复检的实际执行质量。
